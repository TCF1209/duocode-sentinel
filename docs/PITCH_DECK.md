# The final-round deck — ten minutes, ordered by the rubric's weights

Rewritten 25 Sep 2026 for Pitch Day on the 26th, replacing the 24 Sep
five-minute deck. Every number below was re-measured on 25 Sep on the commit
this file ships with (`docs/STATUS.md`, top entry) or carries its source in
the table at the end.

**The deck file is [`Sentinel-final-pitch.pptx`](Sentinel-final-pitch.pptx)
(and a `.pdf` of it beside it)**, generated by `scripts/build_pitch_deck.ps1`,
which drives PowerPoint itself. Seven slides are presented; nine more are
**demo backup** slides — screenshots of every demo beat — hidden in the slide
show and included in the PDF, so a judge reading the submission sees the demo
too. The screenshots are under `docs/img/pitch/` and come from a model-tier
run of this commit on 25 Sep (46 / 20 / 454, 6 model calls). Speaker notes
carry the words. When a number changes, change it here first, then in the
script, then rebuild (PowerPoint closed).

**Format, confirmed by the team on 25 Sep:** a 10-minute pitch with the live
demo inside it, then 5 minutes of questions. Two speakers take turns —
**A = Lim Yee Teng** (the problem, the reviewer's workflow, impact) and
**B = Tang Chye Fong** (architecture, the pipeline demo, the evidence). B
drives the laptop for the whole ten minutes, so the mouse never changes hands;
only the voice does. The click-by-click script is in `PITCH_DAY.md`.

## The rules the deck is built on

1. **Time follows the rubric's weights.** Technical 70 (End-to-End 25,
   Architecture 15, Technology Integration 15, Engineering Quality 15),
   Product & Impact 30 (Effectiveness 10, UX & Differentiation 10, Impact 10).
   End-to-End is scored from what the judges watch working, so six of the ten
   minutes are live.
2. **A strength is said when the screen proves it.** The team's own rule: when
   the demo shows something that earns a high-weight criterion, the speaker
   names it at that moment — the architecture while one case walks the six
   stages, the model's measured effect while "Model answered" appears — not in
   the closing minutes.
3. **"Do not reward the same evidence twice."** Each fact is said once, in one
   place: 11.2 hours only on the live Before view, 168 → 2 only on Compare,
   1.0000 only on slide 5.
4. **"Base scores on what is demonstrated, submitted or clearly explained."**
   Nothing on a slide that cannot be shown or pointed at in the repository.
   Each slide carries a small tag naming the rubric criterion it is evidence
   for; it is never said aloud.
5. **Claim what is true of us, not "only us".** On 25 Sep the other nine
   finalists' public repositories were read (organisers' results endpoint for
   the list; see *What the other finalists changed* below). Several of the
   mentor's "special features" turned out to exist elsewhere, so the deck says
   what Sentinel does, precisely, and never that nobody else does it.

## Slide 1 · Title *(A, 0:00–0:15)*

**On the slide:** Sentinel · *Every answer comes with its evidence.* · the
hook line · DuoCode, both names, APU · the dashboard and repository URLs · a
capture of the run page.

**Say:** "Good morning. We're DuoCode — I'm Yee Teng, this is Chye Fong. A
checker that is confidently wrong is worse than none: nobody goes back to
look. So Sentinel has one rule — it never reports a discrepancy it cannot

*"a discrepancy it cannot prove", not "anything": `email_145` is a masked

## Slide 2 · Why we built it *(A, 0:15–0:50)* → Effectiveness

**On the slide:** the problem statement's four capabilities in its own words
(Classify · Extract · Compare · **Ask for help**, the fourth highlighted);
~4 min a pair, ~20 s an email, "1 field missed becomes a correction, a delay,
rework" — labelled *our own estimate, not a measurement*; the fourth case.

**Say:** "Why we built it. A shipping desk gets five kinds of email in one
inbox. For every document check, a clerk compares the Shipping Instruction
with the draft Bill of Lading — seven fields, manually. Our own estimate:
about four minutes a pair. Miss one field and it becomes a correction, a
delay, rework. And sometimes the check can't be done — a scan with no text, a
blank field, the wrong document. That has to go to a person with the reason,
not be guessed. Chye Fong."

*Eleven hours is not said here — it is said once, live, on the Before view.*

## Slide 3 · How it decides *(B, 0:50–1:50)* → Architecture

**On the slide:** the six stages numbered 1–6, the evidence gate filled and
drawn as able to overrule the comparison; the model-tier bar under stages
1–3; three decisions, each with its cost in a second colour; a footer with
the deployment (Vercel → Render, Docker, non-root → OpenAI) and the scaling
path.

**Say:** "Six stages, one direction. The unusual one is the gate: it runs
after the comparison and can overrule it. If a value can't be found again in
its own document, we don't report a discrepancy — we escalate. Three
decisions, each with a cost. One: values are compared exactly, never by
similarity — this data has APRIL FINE PAPER TRADING, and the same name with
MIDDLE EAST: two different companies. Our cost: sometimes a person checks a
pair that was fine. The alternative's cost: a wrong Bill of Lading, cleared
silently. Two: rules first, the model only where rules can't read — and every
case records which one answered. Three: one stateless library — the API, the
command line and the tests run the same code. So scaling is more copies;
state sits behind one class, and a database is a one-file change. Let's watch
it run."

*The stage numbers are the demo's map: beat 3 walks one case through them.*

## The live demo *(1:50–7:55)* — the words

Clicks, fallbacks and timings are in `PITCH_DAY.md`, *The ten minutes*. The
spoken lines, in order:

**B · the run (1:50–2:40)** — "This is the live system: the dashboard on
Vercel, the API in a Docker container on Render, the model is OpenAI's
gpt-5-mini. It's processing the organisers' whole inbox — 520 emails, not a
sample. Stage one sorts every email into five kinds of mail; for every
comparison request both attachments are read, compared field by field, and
checked by the gate. [done] Done in [read the seconds off the screen].
Forty-six discrepancies, twenty escalated, each with its reason. And six
model calls — all six are scanned pages the rules can't read. That's where
the model goes."

**B · Before / With (2:40–3:00)** — "The same inbox as a clerk receives it:
124 document pairs among 520 emails — about eleven hours of work at our own
estimate. [With Sentinel] What's left for a person is a work list, not an
inbox."

**B · one case through the stages (3:00–3:50)** — "One case, through the
stages on the slide. Intake: both files identified — a Shipping Instruction
and a draft Bill of Lading. Extract: under every value, the document, the
line, and the label as printed. Here the BL says 'To the Order of' — our
table knows that label means Consignee: labels by meaning. Compare: values
exactly — East Bright against UAB Novakopa, a real discrepancy. [open '1 note
from Sentinel'] And the gate: all fourteen values were found again in their
source before this was reported."

**B · Compare, model off then on (3:50–4:50)** — "Now, what happens when the
rules can't read. This pair uses label wording our table has never seen.
Rules alone: it doesn't guess — it's escalated, and it names the fields it
could not read. [switch on, Compare] With the model on, gpt-5-mini reads
those labels with structured output, and every value it returns is found
again in the document before it's accepted. Now it finds the real
discrepancy — marked 'Model answered'. We measured this on 188 documents with
wording we invented: rules alone escalate 168; with the model, two — and
false discrepancies stay at zero. Yee Teng — how a reviewer uses it."

**A · patterns (4:50–5:15)** — "Sentinel also looks across the inbox. These
are the six largest of twenty-one patterns: the top one is seven cases from
one shipper, all with a discrepancy on gross weight. Pattern alerts were on
our round-one roadmap — now built."

**A · shipper history, a correction, the reply (5:15–6:10)** — "On the field
itself: same shipper, same field — six other cases in this run. It counts
only this exact company, not its namesake without 'Middle East', because
values match exactly. The original is one click away. Say the shipper
confirms the weight: [edit] the same rules compare it again — now consistent,
and the extracted value stays on record, struck through. [Draft reply] The
reply is drafted from the reviewer's decision — it now asks only about the
container count. The facts are locked; the model may only reword the
greeting and the closing. A person still presses send."

**A · a scan (6:10–7:00)** — "An escalated case: both documents are scans
with no text layer, so Sentinel did not decide. The model transcribed each
page for the reviewer — seven fields each — as evidence, not a verdict. The
reviewer ticks what they checked against the image…" — then one of the two
branches in `PITCH_DAY.md` (the transcription may or may not misread a name;

**A · amended documents (7:00–7:40)** — "This request arrived with its

**A · against the usual alternatives (7:40–7:55)** — "Today this is a clerk

## Slide 5 · How we know it holds *(B, 7:55–8:50)* → Engineering

**On the slide:** four cards — *Not memorised* (1.0000 × 4, 225 planted, 80/80)
· *Attacked ourselves* (16 kinds of damage, 3,008 documents, 20,496 reads, 13
unchanged, 0 invented discrepancies, OCR 982 → 0) · *Outside the organisers'
data* (real forms, scans, archived BLs, 14,326 emails; most real layouts not
read yet; 0 wrong automatic decisions) · *Engineering* (763 tests, CI on every
push to main, no key/no network, $2 cap then escalate, non-root container) —
and the honest box: `email_145`, the guard that would flag 114 of 124 pairs
(92%), and what is not built yet.

**Say:** "What a demo can't show: how we know it holds. 1.0000 on the
organisers' scorer — and on three more datasets from seeds we never developed
against. But a perfect score on the data you were handed doesn't prove the
reader works. So we damaged our own documents: sixteen kinds of damage, 3,008
documents, no answer key. Thirteen change nothing; under OCR damage, silently
wrong values went from 982 to zero. Then real documents from outside that
data — carrier forms, scans, fourteen thousand emails. It can't read most real
layouts yet, and it made zero wrong automatic decisions: what it couldn't read
went to a person. 763 tests on every push to main. And the one we haven't
fixed is on the slide — a defect we hide is worse than one we miss. Yee
Teng."

*"982 → 0" is the OCR mode only; 74 silently changed values remain under the
`wrapped_value` mode (`ADVERSARIAL.md` §2). Never say "zero silent errors"
without "under OCR damage".*

**Say:** "Impact. The first user is one documentation desk — the inbox

already built."

## What the other finalists changed (25 Sep)

The organisers' public results endpoint lists the ten finalists: Blockeris
(Ship Happens), Coffee Max (NavisAI), DuoCode (Sentinel), Grabbers
(DocuVerify), Hokkien Mee is Black (Shiptuationship), Jbisone (DocuMatch), La
Peace, larpers (ClearDraft), MozartAI (CargoGuard), NJHL (HolyShip). Nine
public repositories were read (Hokkien Mee's returns 404). What it changed in
this deck:

- **Not claimed as unique, because others have them:** re-check on an
  amended document (MozartAI), the source line under each value (most),
  scans transcribed for a reviewer (T4F, MozartAI, ClearDraft), a reply
  actually sent (Blockeris, NJHL), "rules decide, AI assists, a person
  confirms" (almost everyone), a near-perfect score on the organisers' data
  (most).
- **Said precisely instead:** the evidence gate re-checks every compared
  value — rule-read or model-read — before any verdict (others check only the
  model's answers, or only after the fact); the perturbation harness with its
  failures published; the real-document test with its downside attached.
- **Where others are ahead, answered in Q&A, not hidden:** databases,
  accounts, mailbox connectors, heavier AI (`PITCH_DAY.md`, *Questions*).
